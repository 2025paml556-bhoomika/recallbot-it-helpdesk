# RecallBot V06

Corporate IT helpdesk bot for PCA MZG517 Mini Project 1 (variant V06, twist A: multi-user isolation).

**Chat model (every configuration):** `qwen2.5:3b` served by [Ollama](https://ollama.com).
**Tokenizer (when a response has no usage field):** `Qwen/Qwen2.5-3B`.
**Context window:** 4,096 tokens. **Short-term window k:** 4 turns.

## Setup

Python 3.10 or later.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Ollama must be running with the chosen model pulled once:

```bash
ollama pull qwen2.5:3b
ollama serve   # if it is not already running
```

## Run

Step 1 check — one chat call, logged to `logs/calls.jsonl`:

```bash
python -m src.llm_smoke
```

From a fresh shell the same call is:

```bash
python -c "from src.llm import chat; print(chat('Say hello'))"
```

`RUN_ID` defaults to `r01`. Set a new id for every later run (do not edit old log lines):

```bash
RECALLBOT_RUN_ID=r02 python -m src.llm_smoke
```

The dialogue loop is `python -m src.agent "Can someone come to my desk?"`. Slot questions and the confirmation are fixed lines. A tool result is phrased at temperature 0, and an open turn (a greeting, a noted fact, a refusal) is reworded at temperature 0.7 and top-p 0.9. Both read `skills/system_prompt_v1.md`; the booking steps are added only for a visit. The diagram is `docs/architecture.md`.

## Layout

| Path | Role |
|---|---|
| `src/` | Pipeline code. `config.py`, `logger.py`, `llm.py` land in Step 1 |
| `skills/` | `system_prompt_v1.md` and `book_slot_steps_v1.md`, loaded from disk by `load_skill()` on every reply |
| `tests/` | pytest, including the Step 1 log and config checks |
| `data/kb/` | IT helpdesk documents (Step 2) |
| `db/` | SQLite helpdesk database (Step 5) |
| `index/` | FAISS index and chunk metadata (Step 4) |

Build the dense index from `data/chunks.jsonl`, then search it:

```bash
python -m src.vector_index
python -m src.search_kb "What does ERR-VPN-809 mean?" --mode hybrid --size 128
```

`vector_index` writes `index/kb.faiss` (a flat inner-product index, exact search over a small corpus) and `index/kb_meta.jsonl` (the chunk text and metadata, in the same order as the vectors). Both are regenerated by that command, so they are not committed.

`search_kb` takes `--mode dense`, `bm25` or `hybrid`. Hybrid does not add the two scores. It passes the two ranked chunk-id lists to `src.rrf.fuse` (k=60) and returns that order. Hit rates for the 27 questions are written by:

```bash
python -m src.eval_retrieval
```

That writes `results/hit_rate.csv` (3 methods × 2 chunk sizes, plus code and reworded rows) and `results/hybrid_cases.json` (one question hybrid fixed, one it did not, with all three rankings).

Flat against HNSW, for the one-year index size (Task 5(b)):

```bash
python -m src.bench_index
```

Prints the vector count after one year (knowledge-base chunks plus 100,000 users' facts and episodes, taken from `data/test_conversation.json`), the bytes for a flat float32 index and for HNSW with M=16 using the FAISS per-vector formula, query latency of both on 100,000 vectors, and HNSW recall against flat on `data/kb_questions.json`. The same numbers are written to `results/bench_index.csv`. `--n` raises the vector count and `--queries` the number of timed queries. The run embeds the chunks, so the first call downloads `all-MiniLM-L6-v2` if it is not cached.
| `memory/` | Semantic and episodic stores (Steps 7–8). Profile facts are `os`, `laptop_model`, `office`, `floor`, `department`, `manager`, `contact_time`, `vpn_client`, `personal_phone`, read off the sentence. An episode's importance (1 to 10) is the rule in `rate()` and is logged as `importance`. Ending a session writes a reflection, logged as `reflect`, which the next session retrieves |
| `logs/calls.jsonl` | Append-only call log. Never edit lines |
| `results/plots/` | Token and evaluation plots |

## Logging

`src.logger.log_call()` only appends. Each successful LLM call adds one JSON line with `ts`, `run_id`, `config`, `call_type`, `model`, `input_tokens`, `output_tokens`, `retrieved_tokens` and `latency_ms`. Token counts are the API's `prompt_eval_count` and `eval_count`. A failed call writes nothing.

A new line uses `call_type` `chat`, `nlu`, `embed`, `tool`, `summary`, `extract`, `importance`, `reflect` or `judge`. The older names `reply`, `summarise` and `embedding` are no longer written. Lines already in the file keep the name they were written with, and are not edited. `config` on a new line is one of `full`, `trim`, `summary`, `no_rag`, `hybrid`, `hybrid_sem`, `hybrid_mem`. A line from before this field was filled in has `config` null.
