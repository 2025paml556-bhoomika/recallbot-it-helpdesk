Problem statement and your variant 
Build RecallBot, a task-oriented assistant for your assigned domain, following the 
conversational agent pipeline from CS2. It answers policy and FAQ questions from 
a knowledge base with hybrid retrieval, completes one task through slot filling, and 
remembers a returning user across two sessions. 
RecallBot has three parts: 
1. Dialogue pipeline. NLU (intent and entities), a state tracker, a dialogue manager and NLG. At 
least three tools: search_kb(query) (your hybrid retrieval), a database read (for example 
get_order) and a database write that the user confirms before it runs (for example book_slot). 
Use SQLite or JSON for the database. 
2. Knowledge base. At least 15 domain documents (policies, FAQs, service notes), 4,000 to 8,000 
words in total. Include at least 10 codes or IDs (plan codes, error codes, item IDs) and at least 2 
documents that exist in an old and a new version (for example a 2025 and a 2026 refund policy). 
3. Memory system. Four kinds of memory, placed as CS5 recommends: what is read every turn 
stays model-native; what must persist and scale goes to an external store.

Mandatory logging. Every LLM, embedding and tool call writes one line to logs/calls.jsonl: 
{"ts": "2026-11-20T14:03:11.482+05:30", "run_id": "r07", "config": "hybrid_mem", 
"user": "U1", "session": "A", "turn": 12, "call_type": "chat", "model": 
"llama3.1:8b", "input_tokens": 1432, "output_tokens": 118, "retrieved_tokens": 610, 
"latency_ms": 2210} 
• config is one of full, trim, summary (Task 2) and no_rag, hybrid, hybrid_sem, hybrid_mem 
(Task 4). 
• call_type is one of nlu, chat, summary, extract, importance, reflect, embed, tool, judge. 
For a tool call, log 0 tokens and the measured latency. 
• retrieved_tokens is the number of tokens of knowledge-base chunks, semantic memories and 
episodic memories placed in the prompt (0 when nothing is retrieved). 
What the log is and why it matters. The log is a record your code writes automatically while RecallBot 
runs, one line per call; you never write it by hand. Your token plots (2b), comparison table (4a) and cost 
estimate (5a) must be computed from it, and evaluators recompute those numbers from your log to 
check the report. A missing, edited or inconsistent log triggers gate G1. 
A small helper called after every LLM, embedding or tool call is enough:

import json, time, datetime 
 
RUN_ID = "r01"  # change for every run 
 
def log_call(config, user, session, turn, call_type, model, 
             input_tokens, output_tokens, retrieved_tokens, start): 
    """Append one line to logs/calls.jsonl. `start` is time.time() taken just before 
the call.""" 
    rec = {"ts": datetime.datetime.now().astimezone().isoformat(), 
           "run_id": RUN_ID, "config": config, "user": user, 
           "session": session, "turn": turn, "call_type": call_type, 
           "model": model, "input_tokens": input_tokens, 
           "output_tokens": output_tokens, 
           "retrieved_tokens": retrieved_tokens, 
           "latency_ms": int((time.time() - start) * 1000)} 
    with open("logs/calls.jsonl", "a", encoding="utf-8") as f: 
        f.write(json.dumps(rec) + "\n")

Task 3. Retrieval and long-term memory (6 marks) 
• (a) Chunking and indexing (1). Chunk your knowledge base at two sizes (for example 128 and

• (c) Semantic memory of the user (1). An extraction step turns user turns into keyed records 
(user, key, value, source_turn, date, status), like the CS5 fact notebook; filler turns 
produce no record. Report extraction precision and recall against the facts planted in Task 1. An 
update marks the old record superseded, so a stale fact cannot win (the same fix as the stale-
chunk failure in CS4). A forget request deletes the record from the store and the index. 
• (d) Episodic memory (1). Keep a memory stream: time-stamped entries of what happened, each

FAQ 
1. Can I use ChatGPT, Claude or Copilot? Yes, for code, debugging and drafting knowledge-base 
documents. Declare it in Appendix A. You still need to explain every part of your submission in 
the video and, if selected, in the viva. 
2. Which LLM should I use? Do I need a GPU? Any chat model works: a free API tier, or a small 
local model through Ollama on CPU. Use the same model for all configurations so comparisons 
are fair. No GPU is needed. 
3. Can I use LangChain or LlamaIndex? Not for retrieval, fusion or memory. You may use an LLM 
SDK, an embedding library and a vector index such as FAISS. The point of the project is that you 
write BM25, RRF, the episodic score and the memory logic yourself. 
4. How do I mark probe answers? By hand, or with an LLM judge that you check by hand on at 
least 20 judgements; report the agreement rate. Record judged_by for every row. 
5. My system fails some probes. Will I lose marks? Not for honest failures. A failure traced to the 
right stage with evidence earns the error-analysis marks. Perfect results that the logs do not 
support are penalised under gate G1. 
6. How should I rate importance for episodic memory? Either a rule (for example bookings and 
complaints score high, small talk scores low) or an LLM prompt that returns a number from 1 to 
10, as in the CS5 memory-stream example. Explain your choice and log the calls as importance. 
7. Can I generate the knowledge base with AI? Yes, as long as it fits your domain and contains the 
required codes, old and new versions and enough detail for 25 questions. Check it for 
contradictions; your probes depend on it. 
8. What happens if my video runs over 5 minutes? Only the first 5 minutes are marked.
